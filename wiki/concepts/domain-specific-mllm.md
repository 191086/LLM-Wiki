# 领域专用多模态大模型（Domain-Expert MLLM）

**定义**：在通用 MLLM（多模态大模型——视觉编码器 + 语言骨干，同时理解图像/视频与文本）基础上，用领域数据、领域训练与标准化领域评测构建的垂直方向模型，及其配套的「领域模型-数据闭环-基准评测」栈；[[ostrakon-vl]] 是餐饮零售（FSRS，Food-Service and Retail Stores）方向的第一个统一栈。论文的宏观判断：MLLM 正把垂直行业从「单模态分析」推进到「多源证据融合」范式——联合建模文本、图像、表格、图表、视频（[[ostrakon-vl-paper]] §2）。

## 1. 为什么通用 MLLM 不够：三重错位

通用模型的训练目标、真实世界的视觉数据分布、工业界端到端「感知→推理」系统的需求三者系统性错位（[[ostrakon-vl-paper]] §1）。逐层看：

- **能力层**：领域要求识别运营性线索（区分运营招牌与装饰元素）、容忍领域典型退化（橱窗眩光、低分辨率多语言文字、运动模糊、瞬时遮挡）——这些要求在通用预训练 / 对齐数据中基本缺席，通用模型既没见过这些视觉语义，也没被训过对抗这类退化。
- **数据层**：领域数据噪声大、且缺可审计的清洗闭环——朴素 MLLM-as-judge 过滤既不可复现也难查错（对策见 [[quad-data-curation]]）。
- **评测层**：无统一细粒度基准，领域精度既测不准也无从对比（对策见 [[shopbench]]）。

## 2. 领域化的通用配方（以 Ostrakon-VL 为样本）

![[ostrakon-vl-fig1-framework.png]]
> 领域模型三件套的完整框架：上半为 QUAD 数据清洗管线，下半为 CB→OCL→MPO 多阶段训练（论文图 1）。

三件套每件解决一层错位：

**① 数据管线先行（对数据层）**：合成数据 + 可审计的系统性清洗（见 [[quad-data-curation]]），而非朴素 MLLM-as-judge 过滤—— QUAD 的四阶段里阈值全部由「验证集 + 人工审计」标定，每一步可复现可追责。

**② 多阶段训练（对能力层）**，三段各司其职：

- **Caption Bootstrapping（CB，领域知识注入）**：在下游指令微调**之前**，用 FSRS 图像 + 密集 caption（显式描述招牌文字、菜单板、设备、就餐区布局、后厨线索等领域视觉证据）做继续预训练。为什么用 caption：一条 caption 能在单个样本里携带多个实体、属性与关系，为后续指令跟随与推理提供更丰富的「证据词元」，显著改善多模态 grounding（[[ostrakon-vl-paper]] §4.1）。caption 池本身先过 QUAD 的质量过滤与语义去重。
- **离线课程学习（OCL）**：按难度对指令数据分层、由易到难排课，实现从通用感知到领域专长的平滑过渡；难度由参考模型投票判定——准则简单、可审计、给定组件完全可复现（[[ostrakon-vl-paper]] §4.2）。
- **偏好优化（MPO）**：收尾段，用「正确回答 vs 貌似正确的错误回答」的偏好对磨细粒度辨别力与输出稳定性（见 [[mixed-preference-optimization]]）。

**③ 自建基准（对评测层）**：领域分布独立于现有基准、强调视觉证据必要性（见 [[shopbench]] 的 VNR/VIF 指标——分解传统 Multimodal Gain，逼回答必须「看图」）。

## 3. 各领域的成型栈（论文 §2 综述）

| 领域 | 工作 | 是什么（论文原述） |
|---|---|---|
| 金融 | FinTMMBench | 评测基准：跨时序表 / 新闻 / 图表，考察模型的检索与推理能力 |
| 金融 | Open-FinLLMs | 在文 / 表 / 时序 / 图表大规模语料上预训练 + 指令微调，领域适应强于通用模型 |
| 医疗 | BiomedCLIP | 用大规模生物医学图文数据做视觉-语言对齐预训练，放射学相关任务表现强 |
| 医疗 | BrainGPT | 系统级：嵌入具体临床工作流，支持 3D 脑 CT 报告生成与临床导向评测 |
| 生物材料 | Cephalo | 生物材料图文知识连接，端到端整合进下游结构设计 |
| 餐饮零售 | [[ostrakon-vl]] + [[shopbench]] + [[quad-data-curation|QUAD]] | 首个「模型 + 数据管线 + 基准」统一栈 |

共性模式：各领域栈形态不一（有的只有基准、有的是对齐预训练、有的做系统嵌入），但都在「领域预训练 / 对齐 → 领域指令微调 → 领域评测」里至少占两件；Ostrakon 的差异化在于三件齐备且互相咬合（QUAD 产的数据喂 CB/OCL，ShopBench 验证全栈）。医疗一行还示范了更深的整合维度——不止训模型，还嵌进工作流（BrainGPT 的临床报告生成）。

## 4. 参数效率论证与代价

- **域内**：8B 的 [[ostrakon-vl]] 在 ShopBench（60.1）反超 235B 的 Qwen3-VL（59.4）与 72B 的 Qwen2.5-VL（57.3）——通用 scaling 不足以覆盖领域精度，「领域指令 + 训练策略」是小模型的杠杆。
- **域外**：通用基准 72.4→66.7 的回退是已知代价（详见 [[ostrakon-vl]] 页）；领域化本质是能力预算的重新分配而非免费增益。
