# 预切分（Pretokenization）

**定义**：在运行 [[bpe-tokenization|BPE]] 之前，用正则把原始文本切成「词块」（pretoken，通常是单词、数字、标点串）；BPE 的统计与合并**只发生在词块内部**，永不跨越边界——词块因此是一个 token 可能的最大作用域。

## 1. 要解决什么问题：不预切分会学到什么

BPE 只看相邻符号的频次，对「词边界」一无所知。若把整段文本直接丢进去统计 pair，跨词的高频组合会和词内组合一样被合并。走查一个微型反例（机制演示）：语料中 `the time` 反复出现，则相邻对 `(e, ␣)`、`(␣, t)` 也随之高频——不加约束时 BPE 完全可能先学出 `e␣`、`␣t` 这类**跨词边界**的 token。后果：

1. token 不与任何语言单元（词 / 形态素）对齐，词的完整形态无法保证成块；
2. 组合爆炸：跨边界的拼接方式远多于词内组合，词表被浪费在无语言学意义的串上；
3. 上下文耦合：`time` 的切分取决于前一个词是什么，同一词的编码不再稳定。

预切分把 BPE 的作用域限定在词块内，从根上消除这三条——BPE 训练流程的第一步就是预切分并统计词块频次（[[building-a-fast-bpe-tokenizer-from-scratch]]）。两条配套惯例：

- **空格前置**：切分时空格附着在**下一个**词前（` the` 而非 `the `）——「行首的 the」与「句中的 the」由此成为不同 token（[[bpe-tokenization]] §6.4）；
- **英文缩写单独成块**：`'s`、`'ll` 等不与前面的词粘连（正则层面实现，见 §2）。

## 2. GPT-2 预切分正则：五选一扫描

> 正则原文属 wiki 外一般性知识（出自 GPT-2 论文与 tiktoken 源码）；Qwen 沿用同族设计（[[qwen-tokenization-note]]）。

```
'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+
```

扫描从左到右逐位置进行；每个位置按**分支从左到右**的顺序尝试，第一个命中的分支消费一段文本，再从其后继续。五个分支：

| # | 片段 | 匹配 | 例 |
| - | --- | --- | --- |
| 1 | `'(?:[sdmt]\|ll\|ve\|re)` | 英文缩写后缀 | `'s`、`'ll`（弯引号 `’` 不认） |
| 2 | ` ?\p{L}+` | 可选空格 + 字母串 | ` the`、`使用GPT` |
| 3 | ` ?\p{N}+` | 可选空格 + 数字串 | ` 42` |
| 4 | ` ?[^\s\p{L}\p{N}]+` | 可选空格 + 标点/符号串 | ` ...` |
| 5 | `\s+(?!\S)\|\s+` | 空白串 | 换行、连续空格 |

关键记号：

- `\p{L}` 是 Unicode **字母**类别（拉丁、汉字 `\p{Lo}`、假名、谚文……），**不区分文字系统**；`\p{N}` 同理是数字类别。这直接决定中文的行为（§5）。
- ` ?` 的空格是**可选前缀**且至多一个：词间多个空格时，最后一个随词走，其余归第 5 分支（走查见 §3.3）。
- `\s+(?!\S)` 是带**负向前瞻** `(?!\S)` 的空白串：匹配一段空白、但其后不能紧跟非空白——效果是「后面还有字的空白串不吃掉最后一个空格」，把前缀机会留给分支 2–4。

## 3. 手工走查

（以下切分结果均为 Python `regex` 模块对上列正则的实测输出。）

### 3.1 中英混合句

输入：`It's 2026, 使用GPT-4。`

| 词块 | 命中分支 | 说明 |
| --- | --- | --- |
| `It` | 2 ` ?\p{L}+` | 字母串 |
| `'s` | 1 缩写 | 分支 1 排在标点分支 4 之前，`'` 处优先整体吃掉 `'s` |
| ` 2026` | 3 ` ?\p{N}+` | 前缀空格 + 数字串 |
| `,` | 4 标点 | 逗号后无空格可带 |
| ` 使用GPT` | 2 ` ?\p{L}+` | **汉字与拉丁字母同属 `\p{L}`，无空格分隔时进同一块** |
| `-` | 4 标点 | 连字符不是字母/数字 |
| `4` | 3 数字 | 字母/数字边界处必断 |
| `。` | 4 标点 | 中文标点不属于 `\p{L}`，走标点分支 |

### 3.2 弯引号陷阱

输入 `It’s 2026`（U+2019 弯引号）→ `It`｜`’`｜`s`｜` 2026`。分支 1 只认 ASCII 直引号 `'`；弯引号落入标点分支，`s` 被切成单块——一个排版字符的差别直接改变切分。

### 3.3 空白的分工

输入 `Hello,   world  \n end`（词间三空格、行尾两空格 + 换行）：

```
'Hello'｜','｜'  '｜' world'｜'  \n'｜' end'
```

三个词间空格切成 `  ` + ` world`：贪婪的 `\s+` 想吃完三个空格，但末尾空格后是非空白（前瞻失败），回退到只吃前两个（此时后面还是空白，前瞻成立）→ 第 5 分支得 `  `；最后一个空格留给分支 2 作 ` world` 的前缀。同理 `  \n ` 四个空白字符被切成 `  \n` + ` end`。

### 3.4 中文串

输入 `夸张的 比喻手法` → `夸张的`｜` 比喻手法`：按空白分块、空格前置，汉字串保持整块。这条块边界正是词表扩展跨不过去的坎（[[vocabulary-expansion]] §2.1）。

## 4. 与 Sennrich 方案的对比

> 对照细节为 wiki 外一般性知识；候选来源：Sennrich et al. 2016《Neural Machine Translation of Rare Words with Subword Units》。

|  | Sennrich et al. 2016 | GPT-2 以降 |
| --- | --- | --- |
| 词边界表达 | 字符序列上的 `</w>` 词尾标记 | 正则预切分硬边界 |
| 基础单元 | Unicode 字符 | UTF-8 字节（byte-level，[[bpe-tokenization]] §6） |
| 边界保证方式 | `</w>` 参与 BPE 统计，靠频率倾向黏在词尾 | 边界外**物理隔离**，merge 根本看不到跨块 pair |
| 代表 | 早期 NMT | GPT / Qwen 等 LLM |

关键差别在最后一行：Sennrich 的边界是**软标记**，GPT-2 的边界是**硬约束**——不同词块的数据结构互不相见。后者实现更简单、并行更友好（§6）。

## 5. 中文与中英混合

`\p{L}` 不区分文字系统带来一组直接后果（实验验证见 [[pretokenization-cjk-and-mixed-text]]）：

- **连续汉字切成一整块**，直到标点 / 空白 / 数字才断开——预切分**不做中文分词**，「什么是中文词」完全交给 BPE 的频率统计；
- 中英无空格混排进同一 chunk（`使用GPT`，§3.1）；有空格则空格前置，与英文规则一致；
- GPT-2 / cl100k / Qwen2.5 均**无 CJK 专门规则**，差异只在数字切分：GPT-2 整串数字一块（` ?\p{N}+`）；cl100k 最多三位一组（`\p{N}{1,3}`）；Qwen2.5 逐位切（`\p{N}`）——Qwen2.5 实测 `约300B` → `约`｜`3`｜`0`｜`0`｜`B`；
- 对 BPE 训练成本的影响：中文 chunk 平均字节数远大于英文（显式句对实验实测 15.4B vs 4.3B，[[pretokenization-cjk-and-mixed-text]] §4），五级优化阶梯（[[bpe-tokenization]] §8）中的 $L^2$ 项随之恶化——英文基准语料（[[tinystories]]）会低估中文语料的训练成本。

## 6. 工程注记

预切分是可并行的独立阶段（按文档边界切块、多进程处理后合并词频），与串行的 merge 循环解耦——这是 BPE 训练优化的第一刀切分点（[[building-a-fast-bpe-tokenizer-from-scratch]]）。
